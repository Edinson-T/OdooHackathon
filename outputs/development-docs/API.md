# API and Integration Contract — Green Assets

Status: proposed interface for implementation. The hackathon website has **no HTTP business endpoints**. This document defines the asynchronous TypeScript repository used by all screens; it is the integration boundary between UI workstreams and data/rule implementation.

Canonical entity types and exact status values are in [DATABASE.md](DATABASE.md). Implement those in `src/domain/types.ts` and this interface in `src/services/repository.ts`.

## Shared results and inputs

```ts
type ErrorCode =
  | "VALIDATION_ERROR" | "NOT_FOUND" | "FORBIDDEN"
  | "JOB_UNAVAILABLE" | "INVALID_STATE"
  | "STORAGE_UNAVAILABLE" | "DATA_VERSION_UNSUPPORTED" | "DATA_INVALID";

type Result<T> =
  | { ok: true; data: T }
  | { ok: false; error: { code: ErrorCode; message: string } };

type Actor = { actorId: string };

type AssetInput = Pick<Asset,
  "name" | "type" | "latitude" | "longitude" | "zoneId" |
  "inspectionIntervalDays" | "nextInspectionDue">;

// Condition/history are changed through inspections, not metadata edits.
type AssetPatch = Partial<Omit<AssetInput, "type">>;

type CompletionInput = {
  answers: Record<string, "pass" | "fail" | "not_applicable">;
  condition: "healthy" | "needs_attention" | "critical";
  notes: string;
  resolvedComplaintIds: string[];
};

type TriggerResult = {
  createdJobIds: string[];
  updatedJobIds: string[];
  skippedTriggerKeys: string[];
};
```

## Repository methods

All methods return `Promise<Result<T>>`. Actor roles are read from saved User records, never accepted from form input. IDs and timestamps are generated by the repository. Consumers inspect `ok`; expected failures should not become uncaught exceptions.

| Method | Input | Success data |
| --- | --- | --- |
| `getSnapshot()` | None | `Snapshot` |
| `createAsset(actor, input)` | `Actor`, `AssetInput` | `Asset` |
| `updateAsset(actor, assetId, patch)` | `Actor`, ID, `AssetPatch` | `Asset` |
| `submitComplaint(actor, input)` | `Actor`, `{ assetId, description }` | `{ complaint: Complaint; job: InspectionJob }` |
| `claimJob(actor, jobId)` | `Actor`, job ID | `InspectionJob` |
| `releaseJob(actor, jobId)` | `Actor`, job ID | `InspectionJob` |
| `completeJob(actor, jobId, input)` | `Actor`, job ID, `CompletionInput` | `{ job: InspectionJob; asset: Asset; complaints: Complaint[] }` |
| `createDueJobs(asOfDate)` | Local date string `YYYY-MM-DD` | `TriggerResult` |
| `simulateHazard(input)` | `{ type: "rainfall" \| "flooding"; zoneId: string }` | `{ event: HazardEvent; result: TriggerResult }` |
| `replayHazard(eventId)` | Existing event ID | `TriggerResult` |
| `resetDemo()` | None | `Snapshot` |

The last four methods are demo/system utilities. UI identity switching is provider state, not an authentication method. Reset also selects the default community identity in the provider. After creating/updating an asset, the provider invokes `createDueJobs(today)` before refreshing; surface an error if that follow-up fails.

## Validation and side effects

| Operation | Rules |
| --- | --- |
| Create/edit asset | Admin required. Name 1–80 trimmed characters; known type/zone; latitude -90..90 and longitude -180..180, inside the selected zone's bounds; real due date; integer interval 1–365 days. Type cannot be edited. Schedule edits fail with `INVALID_STATE` if unfinished jobs exist. New condition is unknown. |
| Complaint | Known actor and asset; description 10–1000 trimmed characters. Create complaint and its trigger/job in one snapshot write. Initial status is open. |
| Claim | Job must be available and unassigned. Re-claim by its current assignee is a no-op success; another actor gets `JOB_UNAVAILABLE`. Completed jobs get `INVALID_STATE`. |
| Release | Assigned actor only; set available and clear assignee/claimedAt. Other actors get `FORBIDDEN`. |
| Complete | Assigned actor only; job must be assigned; exact checklist question IDs, allowed answer values, at least one applicable answer, notes 1–2000 characters. Failed answer cannot yield healthy condition. |
| Complaint review | Resolved IDs must belong to complaints linked to this job, and require healthy condition with no failed answer. Remaining unresolved linked complaints become reviewed_action_needed. Previously resolved complaints stay resolved. |
| Due check | Trigger assets with nextInspectionDue <= asOfDate. Repeating the same occurrence creates no duplicate trigger. Validate a real date, not just its format. |
| Hazard | Known type/zone. Snapshot affected asset IDs at creation; only those assets receive triggers. Each simulate call represents a new event; replay reuses an existing event. Disable the button while pending to prevent accidental new events. |
| Reset | Require a confirmation dialog in the UI; restore seeds only for the application's storage key. |

Deduplication, merge policy, and priorities follow ARCHITECTURE.md. A successful mutation persists all related changes before returning. On a storage failure, return an error and leave the provider's displayed snapshot unchanged. On success, the provider reloads via `getSnapshot()`; show loading states and disable duplicate submission clicks.

Submitting a completed job again returns `INVALID_STATE` and must not advance its due date twice. A new independent inspection can still be generated by a new complaint, new hazard event, or later due occurrence.

## Example: complaint to inspection

```ts
const report = await repository.submitComplaint(
  { actorId: "user-a" },
  { assetId: "pond-01", description: "The pond outlet is blocked by debris." }
);
if (!report.ok) {
  showError(report.error.message);
  return;
}

const claimed = await repository.claimJob(
  { actorId: "user-b" }, report.data.job.id
);
// Later: render the job's saved checklist, then submit CompletionInput.
```
